How this site was made

Method

I made the analysis section of this site with __N_AGENTS__ Claude Code agents in two rounds, and I set the brief and approved the output at every stage. This page lists each agent with its job, inputs, outputs and run statistics, and the rules and checks every page passed.

Based on the agent records, the __W_RF__ research files, the build script, the screenshot script and the style guide behind this site, 27 October 2026.

Organisation

How the work was organised

The job description was the input. In the first round, research agents ran first, page agents wrote to a shared brief, an index agent read every page, and __W_REV__ reviewers checked the pages independently. A second round added research on banking and Europe, on how Wipro sells and on IT services sales topics, then the A13 Banking Pursuit page, banking edits to five pages, three agents that threaded my account strategy (expand existing accounts first, then open new ones) through the index and eleven pages, and research and pages for the A8 Account Map and A9 New Logos. Scripts checked every page in a browser, and I directed, decided and approved at each step.

Agent pipeline

The first round moved through three agent stages, with my approval between each one. The second round sits in its own band and ran the research and page stages again. Select any agent for its job, run statistics and instructions.

  1. Job descriptionThe job description was the starting point. Each research brief and page brief names the responsibility lines it answers.
  2. First-round research, in parallel__CAP_RES1__ research agents ran at the same time. One agent each covered Wipro, the UK and Ireland market, competitors, and deals, pursuits and workshops. Each wrote a markdown file in which every claim carries a source link, a retrieval date and a flag. I read each file's summary and its list of points to confirm before any page work began.
  3. Page agents and a shared briefIn the first round, __W_PG1__ page agents wrote __W_ANALYSIS1__ analysis pages and the AI Workflow page. One of them also wrote a CV page, which was later removed at my request. All of them read the same page brief, which sets the reader, the sources, the visual standard, the file format and the checks. I decided the page plan and which responsibility lines each page answers.
  4. Index agentOne agent read every finished page and wrote the analysis index, so its summaries and numbers match the pages behind them. A further agent wrote this page from the agent records.
  5. Independent reviewersEach of the __W_REV__ reviewers took four pages and worked from its own review brief. It checked every figure against the research files, applied the writing rules and accessibility fixes, scored the page before and after, and corrected it in place.
  6. Second roundThe second round added __W_R2__ agents and ran the research and page stages again. Research agents covered Wipro's banking and quality engineering offers with European banking regulation, how Wipro sells, and the full scope of IT services sales topics for the role. A page agent then wrote the A13 Banking Pursuit page, and a second agent added banking, Europe and partner material to five existing pages. Both page agents worked to the same page brief, and every page passed the same checks.
  7. Automated checksA Python build script wraps every page with the shared header, navigation and footer. A Playwright script then opens each page at 1,440 px in light mode and 390 px in dark mode, records sideways scroll and console errors, runs an axe-core accessibility scan and saves full-page screenshots for the agent to read.
  8. My partI wrote and approved each brief, chose the research topics and the page plan for both rounds, read the research summaries and the review reports, and decided what changed before each stage moved on.

Research files

Claims in the research files

Every claim in a research file sits in a table row with a source, a retrieval date and a flag. Verified means a primary source such as a filing, a statute or a company release. Secondary means press, analyst or broker coverage. Pages use unverified claims only when they are labelled "to confirm".

Rules

Rules every page followed

A short style guide set the rules for every page, and both the page agents and the reviewers worked to it. These are its rules, grouped by topic.

Sources

Facts come only from the research files and my CV. Every page ends with a Sources panel, and each source is marked primary or press. Claims flagged unverified appear only when labelled "to confirm".

Labels for judgement

Ratings and forecasts carry "My estimate". Model defaults carry "Placeholder figures" and a line inviting the reader to enter their own. Example messages carry "Draft message to test".

Plain writing

Short sentences, usually under 20 words, with one idea in each. Headings name the topic. The pages use British spelling, full sentences and the first person.

Writing for a Wipro reader

Findings are presented as an outside reading from public sources, with what would confirm them. The pages name no individuals beyond Wipro's chief executive, chief financial officer and Europe chief executive, and the Wipro, Capco and Designit leaders the Account Map cites from public sources with their published titles. They use no Wipro logo or brand colours.

Showing on screen

Anything important is visible without hovering, and tooltips only add detail. Each chart has a one-sentence plain reading under its title.

Accessibility

Selectable chart parts take keyboard focus and respond to Enter. Colours come from shared tokens checked in both themes. Each page passes an axe-core scan with no violations and has no sideways scroll at 390 px.

Words and forms the pages avoid

The style guide lists hype words and sentence patterns to leave out. Em dashes, contrast formulas, rhetorical questions and closing summary lines are left out too.
